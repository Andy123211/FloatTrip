# 高德本地请求缓存

生产 HTTP 工具统一复用 `app/core/amap_cache.py` 的 SQLite 缓存，默认文件为项目下 `data/amap-cache.sqlite`，无 Redis 时仍可跨进程重启复用。景点文字搜索、周边搜索、天气、公交/驾车/步行估计及前端步行路线接口均接入。Redis 的 POI 键升级为 v2，包含类型、数量和页码，旧的不完整键不再使用。

只缓存高德成功响应；限流、余额/额度错误、HTTP 错误和异常不缓存。正常的空景点结果缓存 15 分钟。完整查询参数参与键：城市、搜索词、类型、页码、数量、起终点、交通策略等均不同则不复用。密钥和签名不存入缓存键或数据库。

| 数据 | 本地有效期 |
|---|---:|
| 景点文字、周边、详情 | 7 天 |
| 成功但为空的景点结果 | 15 分钟 |
| 步行路线 | 24 小时 |
| 公交、驾车估计 | 15 分钟 |
| 天气 | 30 分钟 |

同一异步事件循环内的并发同请求合并为一次查询；同步调用也有锁。多个独立进程共享已写入的缓存，但同时首次未命中的进程仍可能重复请求。SQLite 失败时记录警告并回退联网。缓存是历史查询结果，不构成未来旅行日期的开放、交通或预约保证。

可设置 `AMAP_CACHE_PATH` 指定可写位置；`AMAP_CACHE_ENABLED=0` 暂停此本地缓存。默认有效期在模块 `TTLS` 中明确版本化。现存 Redis 天气缓存采用自己的有效期。缓存文件不应提交到源码仓库。

本轮四城实验的算法快照没有改动；第 1–415 次仍保留原冷缓存政策，第 416 次起通过独立、冻结并校验哈希的 `cache_worker.py` 包装高德 HTTP 调用，三组共用实验专属缓存。种子只来自之前真实高德成功响应，保留原采集时间，绝不导入评测答案。每条试次保存缓存政策、命中、响应哈希、原始采集与到期时间及来源；报告将本地命中与实际联网分开计数。

策略中途变化与一次沙箱网络事故均保留记录，因此不能把全体结果描述为统一缓存条件的实验，也不能把缓存带来的延迟减少归因于算法。

可离线复用已有试次的成功响应（不会请求高德，也不会刷新原采集时间）：

```bash
.venv/bin/python -m scripts.seed_amap_cache --records artifacts/travel-benchmark/four-city-v2/runs
```

新建三组实验时，默认从第1次就启用独立实验共享缓存；不会恢复旧的逐次冷缓存设置。本轮保存的包装层维持原哈希；日常生产实现还显式关闭每次SQLite连接，避免长时间运行积累连接资源。
