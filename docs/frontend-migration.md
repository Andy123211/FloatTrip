# 途见网页端：浅蓝玻璃界面

入口仍为 http://localhost:8765，由现有 FastAPI 提供静态页面和 API。继续使用 React / 浏览器 Babel，未修改后端协议、账户与行程数据结构。

## 视觉与品牌

保留“途见 / FloatTrip”，以地平线和延伸轨迹替代小鸭。统一为淡蓝、雾白与炭黑的单一风格，移除四主题切换。根据最终反馈，采用苹果系统风格的半透明玻璃面板、胶囊导航、柔和阴影与系统字体；移除展示性英文标签、装饰轨迹、页面分割线和原有暖金色覆盖样式。

品牌 SVG 位于 `frontend/assets/brand/horizon.svg`；`frontend/brand.jsx` 提供内联 SVG 和共享弹窗焦点管理。`frontend/favicon.png` 为由同一 SVG 渲染的 180×180 触屏图标。字体优先使用平台系统字体，不依赖远程字体加载。入口静态资源统一使用 `20260919-horizon` 版本。

首页保留计划 / 解析模式、单次提交、登录续接和真实行程列表。目的地入口合并，点击后填入并聚焦输入框；无行程、未登录、加载和错误各自展示明确状态。

## 工作区与手机适配

桌面端继续使用持续对话、逐日路线和地图；保留分隔条拖动与键盘调整、历史对话、需求确认、SSE、等待回复、停止 / 重试、归档与画像能力。

900px 及以下提供“对话 / 行程”和“路线 / 地图”两级切换。组件保持挂载，切换不清除会话输入、编辑草稿或地图实例；打开规划结果会切到行程。原有跨日编辑、撤销重做、保存失败后重试、离开确认、地点替换及资料草稿仍然有效。手机地点抽屉使用更高不透明度，避免背景文字影响阅读。

登录和画像弹窗支持焦点约束、Esc 关闭与关闭后返回触发控件。关键触摸操作保持至少 44px；适配减少动态效果。SVG 示意地图明确提示缺少坐标或服务不可用，不伪造真实地图加载成功。

嵌入式对话区采用透明滚动轨道、低对比度圆角滑块和 12px 上下边缘渐隐，悬停或键盘聚焦时增强滑块反馈。滚动区域可通过 Tab 聚焦并使用键盘翻页；高对比度模式关闭渐隐并恢复系统滚动条配色。

地点详情抽屉顶部显示该地点已有的 `photo` 实景照片，采用 8:5 圆角横图。提供加载、缺图和加载失败状态；切换地点时重置照片状态，不使用随机图库补图。

规划进度滚出视口时，输入框上方居中显示三颗淡蓝玻璃圆点的轻跳动状态，替代左侧矩形任务卡；点击可定位详细进度，停止入口仍在输入框。等待回复时显示静态提示，减少动态效果模式禁用跳动与平滑定位。

规划完成耗时使用 Run 的 `started_at` 和 `finished_at`，历史恢复不再用页面打开时间作为终点。终态事件到达后读取最终 Run 记录；缺少完成时间时省略耗时。该值为任务开始到结束的墙钟耗时，并非模型纯推理耗时，可能包含工具执行与等待用户回复。

每天标题按全天景点名称和可用的 POI 类型、语义标签归纳为简短主题（如“老城人文漫游”“古镇园林寻幽”）。正常求解和降级求解使用同一套确定性命名规则，不增加模型请求。历史详情只在返回副本中转换原先“前两个景点用与连接”的机器标题及空标题，保留其他主题；不批量修改数据库或路线。相关回归：`python -m pytest tests/test_day_themes.py tests/test_attraction_optimizer.py tests/test_tip_enrichment.py -q`。

### 保存行程卡片与 @ 引用

对话中的历史方案使用玻璃卡片，展示真实首日景点封面（无图时用淡蓝背景）、日期、版本及保存时间，分别提供查看与引用操作。输入 `@` 或 `@目的地` 打开选择列表，支持上下键、回车选择、Esc 关闭、中文输入法和分页读取更早记录；未选择的文字不会自动按标题绑定行程。

引用保存为输入框中的可移除标签，通过现有消息接口的 `related_itinerary_id` 传递唯一行程 ID，优先于右侧打开的行程。消息正文同时记录可读的 `@名称 · 日期 · 版本`，历史恢复后仍可识别。引用在同一对话内保持到用户移除或替换；切换对话清除，发送失败保留草稿与引用。已有任务处理或等待补充时，不允许更换引用，以免把回复发送到错误任务。服务端继续执行原有行程归属校验，无新增 API 或数据库结构。

回归入口：`node --test tests/chat-state.test.js tests/navigation-state.test.js`、`python -m pytest tests/test_frontend_delivery.py tests/test_runtime_api.py`；启动本地服务后可运行 `ego-browser nodejs -e "$(cat tests/itinerary-mentions.browser.mjs)"` 验证隔离样例中的引用、失败重试、分页和响应式布局。

### 等待补充信息

`waiting_user` 在聊天输入框上方显示固定的玻璃卡片，聊天记录只保留简短等待状态。卡片根据明确的输入 schema / 缺失字段显示文本、日期、单选或多选，统一序列化为文本调用原 `/resume` 接口。普通输入在此期间禁用，但草稿和行程引用仍保留；提交失败不清空答案。Esc 仅收起卡片，可再次展开；停止按钮取消当前任务。旧的内部候选池诊断在卡片中转换为可理解的提示。

回归：`ego-browser nodejs -e "$(cat tests/clarification.browser.mjs)"`，使用页面隔离 API 验证输入类型、失败重试、取消、响应式布局及手机键盘可视高度。
